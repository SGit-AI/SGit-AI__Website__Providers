# providers.sgit.ai — the index of the provider reports

The hub for a family of independent provider reports, organised around one question:
**where does the API credential live, and what bounds it.**

Each provider gets its own site, with its own labs, its own cost table and its own claim
ledger. This repository holds only what is *shared*: the four credential patterns, the
claim-state model, the page contract every site in the family obeys, and the comparison
tables — which are **synced from the provider sites rather than written here**.

## The one rule that shapes the repository

**This hub makes no measurement of its own.** It runs no API, ships no lab and asks for no
key. Every number in its tables comes from the provider site that produced it, is fetched
by `bin/sync-providers.py`, and is written into `data/providers.yml` with the sync date and
that site's version attached. The build then reads that file and never touches the network.

```
bin/sync-providers.py            # fetch each provider site's front-matter + claim index
bin/sync-providers.py --check    # report drift without changing anything (CI-shaped)
```

The consequence is deliberate: if a row is wrong, it is wrong on the provider's own page
first, and the correction belongs there. A hub that keeps its own copy of other people's
properties will drift from them, and it will be the hub that is wrong.

## Layout

```
build.py                 the whole build — markdown subset, shortcodes, claim join
content/*.md             the nine pages, front-matter + markdown
data/providers.yml       generated by bin/sync-providers.py — do not edit by hand
data/claims.yml          the hub's own claims (six; the measurements live elsewhere)
assets/                  one stylesheet, one script, one favicon — all self-hosted
tools/check_site.py      the acceptance gate (20 checks)
tools/secret-scan.sh     10 patterns, whole tree including docs/
admin/build/version.txt  the single source of truth for the version
bin/bump.py              moves it, and only it
docs/                    the built site — committed, because Pages serves it
```

## Building

```bash
python3 build.py                 # writes docs/
python3 build.py --check         # fails if docs/ does not match the sources
admin/build/validate.sh          # everything CI runs, in one command
```

## Releasing

The estate convention, unchanged here: one file owns the version, the release commit's
subject repeats it, and CI refuses to tag if the two disagree.

```bash
bin/bump.py minor                              # or patch / major
git commit -am "site v0.2.0: what changed"
git push -u origin dev
```

## DNS

Neither `providers.sgit.ai` nor `elevenlabs.providers.sgit.ai` is pointed at its repository
yet, so both sites serve from their GitHub Pages project paths. The site is built entirely
with page-relative URLs and is checked for that (`check_relative_urls`), so it works at a
domain root, a project path, a local directory or a vault frame without changes — and
`check_family_links_live` fails the build if a page links a provider by a canonical domain
that does not resolve. `docs/CNAME` already carries the intended host, so pointing the DNS
is the only remaining step.
